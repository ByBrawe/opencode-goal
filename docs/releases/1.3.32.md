# OpenCode Goal 1.3.32

Long-session liveness and Goal/Loop isolation release.

## Waiting for human or external action

- Add a persisted `waiting_user` lifecycle state for Goals that cannot make required progress until the user supplies approval, credentials, deployment/manual action, or otherwise unavailable external data.
- Add `opencode_goal_wait_for_user`. It records why the Goal is sleeping and what is needed, then stops autonomous continuation instead of polling the same dependency.
- Natural-language resume and explicit Goal resume both wake a waiting Goal at the normal idle ownership boundary, preserving steering and turn-ownership safety.

## Progress attribution

- Ignore companion Loop runtime state below `.opencode/opencode-loop` when OpenCode reports workspace patch activity. Scheduler diagnostics and `loop.log` can no longer keep an otherwise stalled Goal alive.
- In Git worktrees, a completed shell command counts as Goal progress only when HEAD or non-control-plane worktree state actually changes.
- Repeated read-only diagnostics, status checks, searches, and remote/live probes no longer reset the no-progress guard merely because their command text differs.
- Goal and Loop persistence paths remain excluded while project-owned `.opencode/*` content outside those control-plane roots remains observable.

## Context and compaction safety

- Before dispatching another autonomous Goal turn, use host-observed context usage plus output/compaction reserve to detect unsafe headroom and request one compaction first.
- Clear stale request/input pressure telemetry after successful native OpenCode compaction so Goal does not immediately request a redundant second compaction.
- Recognize provider bridges that collapse a context failure into generic HTTP 400 `invalid_request_error` only when independent host telemetry already proves critical context pressure.
- Keep recovery bounded: one compaction attempt, then fail-safe pause if the same Goal generation still cannot complete a successful turn.

## Verified

- Focused regressions cover Loop control-plane patch filtering, durable shell/worktree progress, read-only stall behavior, waiting-user sleep/resume, proactive context compaction, the exact generic HTTP 400 shape from the reported session, and native auto-compaction ownership.
- The exact feature head passed CI, Release Readiness, Real Host Progress, Real Restart Recovery, Real Loop Coexistence, and Actions Security Gate, with Ubuntu/Windows and OpenCode 1.4.0/latest compatibility coverage.
