# OpenCode Goal 1.3.35

OpenCode 2.0.11 plugin-loader compatibility hotfix.

## Dual package server entry

- `@bybrawe/opencode-goal/server` now default-exports one object that satisfies both supported host contracts:
  - OpenCode 1.x continues to call the existing stable `server()` implementation.
  - OpenCode 2.x can accept the same package through `setup()` instead of rejecting it at plugin-load time.
- The public root package and stable V1 Goal runtime remain unchanged.

## OpenCode 2 safety boundary

- The new `setup()` path delegates to the already-existing experimental V2 adapter.
- That adapter remains intentionally read-only for Goal lifecycle control on current OpenCode 2 hosts.
- This release does not claim full Goal V2 lifecycle parity and does not bypass the command-origin or request-time tool-materialization safety gates.

## Exact 2.0.11 validation

The feature head passed the repository's full required gate set before merge:

- CI
- Actions Security Gate
- Release Readiness
- Real Host Progress
- Real Restart Recovery
- Real Loop Coexistence
- Experimental OpenCode 2 Host

The OpenCode 2 workflow includes a dedicated exact `2.0.11` real-host job that builds the production package server entry, loads it through OpenCode, and requires `@bybrawe/opencode-goal` to reach active plugin state.

## Update

```sh
npx -y @bybrawe/opencode-goal@latest
```

Fully restart OpenCode after updating so the process unloads the previous 1.3.34 server module and loads 1.3.35.
