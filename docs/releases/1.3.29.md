# OpenCode Goal 1.3.29

Agent-native resume intent and long-run completion-integrity release.

## Fixed

- Move natural-language paused-Goal resume intent out of lifecycle phrase matching and into the OpenCode agent/model layer. Foreground text stays unchanged in the user's language, paused Goal context is exposed to the model, and the model can call the dedicated `opencode_goal_resume` tool when the user's meaning is to continue/resume/steer the Goal.
- Keep `/goal resume` as the deterministic explicit control path. Questions, status/explanation requests, unrelated chat, and non-paused hard states are not implicitly converted into Goal resume.
- Keep the model's routing turn outside Goal ownership: a successful `opencode_goal_resume` call queues re-entry, then the following `session.idle` boundary activates the Goal and lets the existing scheduler dispatch the normal Goal-owned continuation turn. If the process disappears before that boundary, persisted Goal state remains safely paused.
- Make the remaining implicit runtime cap opt-in for newly created Goals (`maxRuntimeMs: 0` by default). Explicit finite runtime budgets and persisted finite legacy budgets remain hard guards.
- Replace blind 500-record evidence FIFO truncation with audit-aware retention. Current-revision trusted proof records still referenced by requirements and the latest current host/verifier result for each verification key are retained, so long runs cannot silently lose an old proof anchor or forget a newer failure after unrelated evidence accumulates.
- Canonicalize requirement proof pointers to the current proof record rather than accumulating an unbounded list of historical `evidenceIDs`. The normal evidence target remains 500 records; correctness-critical pinned records may exceed that target only when the pinned set itself is larger.

## Safety preserved

- Native OpenCode Todo state remains advisory orchestration telemetry, not completion evidence.
- Independent semantic verification and host-corroborated command/file proof remain required by the existing completion gate.
- Explicit user pause, usage/provider limits, finite user-configured budgets, restricted-agent boundaries, revision ownership, and Loop coexistence remain authoritative.

## Verified

- Added multilingual paused-resume regressions and model-tool/idle-ownership tests, including Turkish, Spanish, Japanese, Arabic, French, Polish, Russian, Chinese, and German foreground text handling.
- Added 500+ evidence-record regressions proving current trusted proof anchors and latest failing verification states survive retention while superseded proof records remain pruneable.
- Validated unit tests, adversarial evals, package import/install checks, and OpenCode plugin compatibility against the minimum supported `1.4.0` API and current latest.
- Validated real OpenCode lifecycle, active steering, compaction continuation, semantic completion, 10-turn completion, same-turn batch rejection, host progress, process restart recovery, and released OpenCode Loop 0.5.35 coexistence on Ubuntu and Windows.
- Release Readiness validates the packed publish artifact on Node 20 and Node 24 across Ubuntu and Windows before trusted npm publishing.
