# OpenCode Goal 1.3.44

OpenCode 2.0.22 SDK-contract and autonomous ownership recovery patch.

## Persisted execution ownership recovery

A Goal-owned turn can outlive the plugin runtime that admitted it. If that runtime
is reloaded before the execution terminal arrives, the in-memory owner map is no
longer authoritative.

1.3.44 recovers that ownership only through OpenCode 2's public
`session.context({ sessionID })` surface. Recovery requires the latest persisted
user message to carry Goal autonomous metadata for the exact current Goal id and
revision. A newer ordinary user message blocks recovery. Settled execution
generations are also remembered so replaying the same terminal cannot enqueue a
second continuation.

This closes #261 without introducing a broad "active Goal means continue" fallback.

## OpenCode 2.0.22 contract

The production `@opencode/plugin` dependency is pinned to exact 2.0.22.

The native adapter now uses the stable minimum
`session.interrupt({ sessionID })` contract and no longer sends the legacy
`continue` field. Compile-time conformance guards cover the interrupt input,
Goal prompt admission subset, and session-scoped context input so a future SDK
change cannot silently drift behind adapter casts.

The moving real-host lifecycle gate passes on OpenCode 2.0.22 while the existing
exact older-host lanes remain as backwards-compatibility coverage.

## OpenTUI peer alignment

Optional `@opentui/core` and `@opentui/solid` peers now require 0.5.14 through
the supported 0.5.x range, matching the OpenCode 2.0.22 SDK peer graph. Production
package smoke and published-consumer verification install that supported peer floor
directly; peer conflicts are not bypassed with force flags.

## Upgrade

```sh
npx -y @bybrawe/opencode-goal@1.3.44
```

Then fully restart OpenCode and verify:

```text
/goal status
```

Existing Goal state, evidence, revisions, budgets, sequence state, handoff state,
and project data are preserved.
