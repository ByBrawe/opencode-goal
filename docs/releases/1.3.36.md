# OpenCode Goal 1.3.36

Goal lifecycle notification release.

## User-authored lifecycle notifications

Goals can now attach an optional local notification command directly to the Goal Contract:

```text
/goal ship release --check "npm test" --notify "my-notifier --goal {goal} --reason {reason}"
```

- `{goal}` expands to the durable Goal ID.
- `{reason}` expands to `completed`, `blocked`, `paused`, or `rejected`.
- `waiting_user`, budget-limited, and usage-limited states map to `paused`.
- Queued Goals preserve their notification command through promotion, and `/goal edit` preserves it unless the user explicitly replaces it.

## Safety boundary

Notification delivery is advisory and happens only after durable Goal persistence.

- Semantic no-op or same-status saves do not duplicate notifications.
- A notification process failure cannot roll back, block, or change Goal state.
- Persisted notification commands are validated fail-closed.
- Model-facing `opencode_goal_*` tools do not expose a notification-command mutation field; only the user-authored Goal command surface can configure it.
- The current runtime fingerprint, no-op save suppression, waiting-user behavior, restart recovery, host limits, queue semantics, and completion verification remain intact.

The implementation ports the useful direction from contributor PR #196 onto the current architecture and was merged in #205.
