# OpenCode Goal 1.3.40

Official OpenCode 2 plugin-definition and package-contract hardening release.

## V2 entrypoints

- The package root `@bybrawe/opencode-goal` now defaults to the same official
  `Plugin.define({ id, setup })` dual plugin definition that OpenCode 2 expects
  when resolving a package from `plugins`. Named library exports remain available.
- `@bybrawe/opencode-goal/server` is defined with
  `@opencode/plugin` `Plugin.define({ id, setup })`.
- `@bybrawe/opencode-goal/v2` is the native-only `Plugin.define()` entry.
- `@bybrawe/opencode-goal/tui` is defined with
  `@opencode/plugin/tui` `Plugin.define()`.
- V1 `server()` and TUI compatibility remain separate implementations. The explicit
  `@bybrawe/opencode-goal/v1` subpath resolves directly to the lazy legacy function;
  the V2 setup path does not translate or execute V1 hook objects.

The official V2 Context is retained at each public boundary; the narrower existing
Goal host interfaces are adapted only behind those boundaries.

## Package verification

The server, native-only entry and shared RPC contract must import from a clean
production installation with TUI peers omitted. The TUI is then verified
separately with the supported host UI peer set:

- `@opentui/core@0.5.12`
- `@opentui/solid@0.5.12`
- `solid-js@1.9.12`

This keeps host UI peers host-owned rather than hiding duplicate renderer runtimes
inside the Goal package.

Before npm publication, the exact current Loop V2 companion source is built and
exercised with Goal on OpenCode 2.0.18. Exact-main Goal gates remain mandatory.

## Preserved semantics

Goal identity, objective/constraints, revision, evidence, cumulative budgets,
same-ID unit handoff recovery, location-bound status RPC and unload fences are
unchanged from 1.3.39. No persisted Goal migration or accounting reset is performed.

## Boundaries

OpenCode 2.0.18 remains the joint native-host baseline; unit handoff compatibility
on 2.0.16 remains separately tested. Deterministic canaries validate behavior and
packaging, not live-model cost, latency or long-duration reliability.
