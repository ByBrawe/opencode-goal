# OpenCode Goal 1.3.27

Cross-plugin command-ownership reliability release.

## Fixed

- Keep foreign/plugin slash-command bridge traffic out of active Goal foreground steering so a companion command cannot repin the Goal executor to its local command agent, model, or variant.
- Correlate command-owned bridge messages with one-time plugin-issued markers, strip valid markers before provider dispatch, and leave spoofed or expired markers as ordinary foreground chat.
- Preserve normal human steering and preemption behavior while maintaining a single autonomous prompt owner for the session.

## Verified

- Reproduced the original collision from a clean environment with OpenCode 1.18.21, OpenCode Loop 0.5.35, and OpenCode Goal 1.3.26 on both Ubuntu and Windows.
- Added real-host coexistence canaries with released Loop 0.5.35 for both post-first-token and first-response-byte-delayed provider states.
- Verified zero autonomous Loop dispatch, zero persisted Loop jobs, zero private marker leakage, and unchanged Goal `build` execution ownership on Ubuntu and Windows.
- Re-ran the existing human steering, lifecycle, compaction, semantic completion, progress, restart recovery, compatibility, unit/eval, and package smoke gates.

See `docs/CROSS-PLUGIN-OWNERSHIP.md` for the ownership contract and host-edge behavior.
