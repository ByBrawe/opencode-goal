# OpenCode Goal 1.3.45

Semantic-verifier scale and evidence-hardening patch.

## Long-running OpenCode 2 semantic verification

Issue #263 exposed two different failure classes on large sessions: the verifier
could hit an inflexible short deadline, and a real verifier-child/provider failure
could be hidden behind the later generic timeout.

1.3.45 uses a five-minute native V2 primary verifier deadline by default. It can
be overridden per plugin with:

```json
{
  "package": "@bybrawe/opencode-goal@1.3.45",
  "options": {
    "verifierTimeoutMs": 420000
  }
}
```

or with `OPENCODE_GOAL_VERIFIER_TIMEOUT_MS`. Values above 60 seconds are valid
for the primary audit. The one automatic fresh-session timeout retry remains
bounded to at most 60 seconds, and there is still no third automatic retry.

When no explicit verifier model is configured, V2 resolves OpenCode's built-in
`title` agent model—the public normalized equivalent of legacy `small_model`—
and applies it to the verifier child through `session.switchModel()`. An explicit
`verifierModel` / `OPENCODE_GOAL_VERIFIER_MODEL` still wins.

Verifier-child `session.execution.failed` events now surface their host/provider
failure reason immediately. Timeout diagnostics separately name the primary and
automatic-retry deadlines.

## Evidence hardening

Semantic/file verification now:

- fails declared-file requirements cleanly when a contract path is a directory or
  another non-regular file;
- recovers only the safe workspace-root-qualified citation shape with a dropped
  root prefix and keeps recovered paths inside the project;
- attempts exact quote matching first, then accepts whitespace-folding-only
  differences;
- keeps hallucinated or materially different quotes fail-closed.

These changes cover the evidence-path/quote regressions reported alongside the
verifier work without weakening host corroboration.

## Release reliability

Windows test cleanup retries transient filesystem-handle removal. Post-publish
consumer verification also retries bounded npm registry propagation so an
already-successful trusted publish does not become a false red workflow solely
because a package edge has not propagated yet.

## Upgrade

```sh
npx -y @bybrawe/opencode-goal@1.3.45
```

Then fully restart OpenCode and verify:

```text
/goal status
/goal audit
```

Existing Goal state, evidence, revisions, budgets, queue state, handoff state and
project data are preserved.
