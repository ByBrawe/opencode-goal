# OpenCode Goal 1.3.39

Native OpenCode 2 sidebar, location-bound read-only status RPC and lifecycle hardening.

This release carries the native server/TUI changes developed after the published
1.3.38 commit 2c21251d65e0f2c2df291f76bd4e92e325934b46. The immutable 1.3.38 npm
package is not overwritten or treated as proof that subsequent main changes shipped.

## Changes

- Native `setup(context)` sidebar with actual OpenTUI rendering, reactive session
  switching, bounded polling and cancellation. V1 presentation remains lazy.
- Shared `@bybrawe/opencode-goal/rpc` contract. Status comes from the connected
  server's verified session location/workspace, never unrelated client-local files.
- Admission, setup rollback and handoff unload guards. Late responses cannot start
  the next host/persistence side effect in a retired plugin instance.
- Same-ID handoff recovery preserves contract, revision, evidence and cumulative
  budgets. Long-objective and separate-constraint checks span three native sessions.
- Unit-command process-tree cleanup and handoff control-state exclusion from progress.
- Publication now waits for ten exact-main gates, including the Windows/Linux
  native sidebar and Node 20/24 installed-package matrix. Previously PR-only native
  stable and Todo-differential gates also run on main.
- Immutable npm collision checks bind version to gitHead. Registry exports,
  dependencies, latest tag, installer version and clean native imports are verified.

## Boundaries

OpenCode 2.0.18 is the native sidebar/RPC and joint-host baseline; 2.0.16 handoff
compatibility is tested separately. This release does not claim every conceivable
V1/V2 option or future host is equivalent. Existing explicit V1 compatibility is
retained, Goal storage is not migrated, and native execution is not aborted merely
because the plugin unloads. In-flight host IO may complete.

Controlled-provider canaries are functional checks, not live-model cost, latency
or long-duration reliability measurements. Publication is complete only after the
publisher's authoritative registry and clean-consumer verification succeeds.
