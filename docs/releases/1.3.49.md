# OpenCode Goal 1.3.49

## exFAT/FAT and hard-link-restricted project storage (#272)

OpenCode 2 Goal no longer requires project filesystems to implement hard links for session locking. When `fs.link()` rejects a lock claim with `EISDIR` (reported on Windows exFAT), `ENOTSUP`, `EOPNOTSUPP`, `ENOSYS`, `EPERM` or `EACCES`, the plugin tries an atomic exclusive-create (`wx`) lock file instead.

The fallback refuses an existing lock (`EEXIST`), preserves process ownership tokens, does not re-use old authorizations, and applies to stale-owner cleanup elections too. An uninitialized exclusive lock receives only a short bounded read retry; corrupt owner metadata and other I/O failures remain fail-closed. No automatic deletion of arbitrary lock files is performed.

Regression tests simulate unsupported hard links, collision timeouts, stale-PID recovery, corrupt lock metadata and unexpected errors. Windows/Linux release gates remain mandatory. **Physical Windows exFAT and SMB environments have not yet been directly tested by this CI.**

## Installation (after npm publication)

```powershell
npx -y @bybrawe/opencode-goal@1.3.49
```

The dedicated Loop package remains independently installed. To receive Loop's corresponding exFAT fix, update it separately after version 0.6.8 is published. Fully exit/restart OpenCode and verify native `/goal status` plus an actual Goal creation on the affected project volume.
