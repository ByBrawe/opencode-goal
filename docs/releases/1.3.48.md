# OpenCode Goal 1.3.48

Native OpenCode 2 continuation-ownership and restart recovery patch.

## Fixed and verified on main

- A plain `continue` wake can regain access to Goal lifecycle tools **only** after the host verifies the exact accepted continuation message and successful execution boundary for the same live Goal revision. Unrelated user messages, Plan/read-only contexts, failed or duplicated terminals do not receive Goal-owned capabilities.
- After a native Goal instance is disposed or an OpenCode 2 host process is killed, reissuing the **native** `/goal create` command in the original session can acquire a *new* one-use control capability. An expired or consumed historical token remains invalid.
- The latter case was reproduced through a real latest-host stop/start with the same session ID and workspace, in addition to plugin-level regressions. Linux/Windows restart, lifecycle, sidebar, and release-readiness gates remain mandatory.

## Boundaries

These checks target issues #269 and #271. They do not assert that a particular external caretaker's long-lived Windows session has been replayed, nor that OpenCode Desktop autocomplete is fixed. Desktop/CLI backend identity is tracked in Loop issue #169.

This is a dedicated Goal package update. Installing Loop does not implicitly install or update Goal; legacy `/loop-goal*` commands remain opt-in compatibility features.

## Upgrade

```sh
npx -y @bybrawe/opencode-goal@latest
```

Fully restart OpenCode after npm confirms version 1.3.48. To also use Loop, install it separately using `npx -y @bybrawe/opencode-loop@latest`.

Goal state, queue, evidence, budgets, verified/continuous mode and host-owned completion authority are preserved.
