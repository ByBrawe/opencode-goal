# OpenCode Goal 1.3.42

OpenCode 2 migration-guide conformance and public-context authority hardening release.

## V2 location and options boundary

The V2 plugin runtime now treats `ctx.location.directory` as the plugin instance's
project location. `ctx.options` is reserved for plugin configuration such as Goal
lifecycle/autonomous options and is never accepted as a project-directory fallback.

Per-session reads and mutations remain stricter: the target session must resolve
through `session.get` with an absolute `location.directory`. A missing or
unrelated location fails closed instead of borrowing the plugin instance location.

Capability probes and telemetry canaries follow the same rule so tests exercise the
same public V2 contract as production.

## Public interruption contract

Semantic-verifier timeout cleanup now uses:

```ts
ctx.session.interrupt({ sessionID, continue: false })
```

This matches the lifecycle mutation path and removes the last stale
`session.interrupt({ resume: false })` request shape from the V2 Goal runtime.

## Plugin migration contract

The package continues to use the V2 `Plugin.define({ id, setup })` root/server and
native-only entrypoints, plural `plugins` installation, native command/tool/session
hooks, abortable event-stream cleanup, and a separately lazy V1 compatibility path.
The V2 default path does not route through V1 client request shapes.

## Verification and preserved state

The existing exact-main release matrix remains mandatory, including Windows/Linux
production package checks, current/experimental OpenCode 2 hosts, restart recovery,
Todo differential, unit handoff, native sidebar and joint Loop validation.

Goal identity, objective, constraints, revision, evidence, cumulative usage, budget
state and same-ID handoff recovery are unchanged. No persisted Goal schema migration
or accounting reset is introduced.
