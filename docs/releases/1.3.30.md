# OpenCode Goal 1.3.30

Long-Goal context-overflow and black/blank-session reliability release.

## Fixed

- Stop Goal's own control-plane persistence from masquerading as user-project progress. OpenCode patch events and file-tool fingerprints under `.opencode/goals`, `.opencode/goal-locks`, and `.opencode/goal-sequences` are ignored by the no-progress detector, while project-owned `.opencode/commands` remains observable work.
- Prevent very large Goal contracts from being appended to model history on every autonomous continuation. The full contract is anchored once per Goal revision; later continuations keep the same Goal-ownership marker plus a bounded objective reminder, and compaction re-anchors the full contract exactly once.
- Avoid duplicating the complete objective through the generated objective requirement in continuation/compaction prompts.
- Bound paused natural-language resume routing so the model gets only a short objective preview and the resume tool never echoes the full Goal contract.
- Classify provider errors such as `[1261] Prompt exceeds max length` as deterministic context pressure rather than retryable network/provider infrastructure. They can no longer enter an endless `provider_retry` backoff path.
- On the first prompt/context overflow, request one OpenCode session compaction with the Goal's bound model, suppress pre-compaction idle races, persist recovery state with stale-generation retry protection, then restore exactly one normal Goal-owned continuation.
- If the prompt still overflows before a successful Goal-owned turn, fail safe instead of looping: keep the persisted Goal paused and tell the user to run `/compact`, then `/goal resume`.
- Clear stale infrastructure-recovery and stall-exemption metadata when a deterministic fatal provider failure pauses the Goal.

## TUI and pasted Goal safety

- Treat meaningful multiline `/goal`, `/goal edit`, and `/goal add` bodies as literal Goal text. CLI examples or documentation containing `--foo`, `--accept`, `--max-turns`, and similar tokens are no longer misparsed as Goal command flags.
- If an outer terminal command such as `opencode run ... @' ... '@` is pasted *inside* the already-running OpenCode TUI, reject it with visible actionable guidance instead of allowing a slash-command hook exception to leave an apparently blank/black command turn.
- Invalid Goal command syntax now produces visible command output plus an optional TUI error toast without mutating persisted Goal state.

## Safety preserved

- Goal state files remain persisted project-locally; the fix changes only whether those internal writes count as work progress.
- Native OpenCode Todo state remains planning telemetry, not completion evidence.
- Host evidence, semantic verification, explicit user pause, finite configured budgets, revision ownership, restricted-agent boundaries, and Loop coexistence remain authoritative.
- Prompt-overflow recovery is deliberately one-shot per failed Goal-owned episode; there is no automatic compaction loop.

## Verified

- Regression coverage reproduces the real provider error shape `HTTP 400 ... [1261] Prompt exceeds max length` and proves it is not transient infrastructure.
- Regression coverage proves Goal persistence PatchParts cannot reset the stall guard, including Windows/POSIX path variants and mixed internal/project patches.
- A roughly 30K-character Goal contract is present once in the initial anchor, absent as a full copy from repeated reminders, and present once in compaction context.
- One-shot prompt-overflow compaction, stale-write recovery, post-compaction ownership handoff, second-overflow fail-safe behavior, bounded paused-resume context, and multiline-paste UX are covered by the unit suite.
- The exact feature head passed CI, minimum/current OpenCode plugin compatibility, real lifecycle/active-steering/manual+automatic-compaction/semantic-completion canaries, 10-turn completion, same-turn batch rejection, host progress, restart recovery, released OpenCode Loop 0.5.35 coexistence, Actions Security Gate, and Node 20/24 package-smoke matrices across Ubuntu and Windows.

## Correct TUI usage

Inside an already-running OpenCode TUI, use:

```text
/goal <your Goal text>
```

For a large multiline Goal, type `/goal ` and paste only the actual Goal instructions. Do not wrap that text in another outer `opencode run` command.

## Update

```sh
npx -y @bybrawe/opencode-goal@latest
```

Fully restart OpenCode after updating so the newly installed plugin version is loaded.
