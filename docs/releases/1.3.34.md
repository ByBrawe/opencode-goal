# OpenCode Goal 1.3.34

Long-session diagnostics and Todo-integrity hardening release.

## Persistence write hygiene

- GoalStore now suppresses saves whose only differences are persistence metadata such as `updatedAt` and `storageGeneration`.
- Optimistic concurrency remains authoritative: stale snapshots are rejected before no-op detection, so reduced write churn does not weaken stale-writer protection.
- Real semantic mutations still advance the storage generation normally.

## Runtime fingerprint diagnostics

- New Goals persist the exact OpenCode Goal package version and a SHA-256 identity of the shipped compiled JavaScript runtime.
- OpenCode host, `@opencode-ai/plugin` API, and companion Loop versions are recorded only when the loaded runtime can discover them safely or they are supplied explicitly.
- Legacy schema-v1 snapshots remain readable without a migration write. The first real save under the current runtime stamps the fingerprint once.
- Stable Goal status and the experimental V2 read-only status expose the persisted runtime identity, making it possible to distinguish an old loaded plugin process from newer code on disk.

## Native Todo drift visibility

- Goal surfaces an advisory warning when more than one native Todo is simultaneously `in_progress`.
- Same-revision regressions from `completed` back to `pending` / `in_progress` are detected and retained across unchanged replay until the plan is repaired.
- Large same-revision plan replacement is surfaced when most prior items disappear and most next items are new.
- These warnings never become Goal evidence, never count as host progress, and never rewrite the native Todo plan.
- A genuine Todo rebuild after `/goal edit` or another Goal revision change remains allowed without same-revision drift warnings.

## Verified

- Focused tests cover semantic no-op saves, stale-writer rejection, legacy fingerprint migration, corrupt fingerprint rejection, multiple-in-progress Todos, completed-item regression, substantial replacement, repair, and revision-bound rebuild behavior.
- Exact feature heads passed the repository's CI, Actions Security Gate, Real Host Progress, Real Restart Recovery, Release Readiness, Loop coexistence, minimum/latest OpenCode compatibility, and experimental V2 safety gates before this release metadata PR.

## Update

```sh
npx -y @bybrawe/opencode-goal@latest
```

Fully restart OpenCode after updating so the loaded plugin process uses 1.3.34 and reports the new runtime fingerprint.
