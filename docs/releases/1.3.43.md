# OpenCode Goal 1.3.43

OpenCode 2 configuration canonicalization and deterministic SDK patch.

## Canonical plugin configuration

OpenCode 2.0.21's runtime schema uses the native plural `plugins` field. Its
configuration normalizer also accepts the legacy singular `plugin` field and
normalizes valid legacy entries into the native list in memory.

The 1.3.43 installer now persists that same normalization instead of leaving two
parallel top-level plugin lists. During a native V2 install:

- legacy string plugin specs remain strings;
- valid legacy `[package, options]` tuples become native
  `{ "package": "...", "options": { ... } }` entries;
- migrated legacy entries keep their order ahead of existing native entries;
- Goal's own registration is de-duplicated and pinned to the exact package version;
- an empty legacy `plugin` property is removed;
- malformed or unrecognized legacy entries are preserved rather than discarded.

The installer does not rewrite unrelated `provider`, `providers`, `model`, or
other user configuration.

## Deterministic V2 runtime dependency

The production `@opencode/plugin` dependency is pinned to exact 2.0.18. This
prevents a later compatible-looking SDK release from changing the package's
dependency graph or introducing unrelated peer-resolution failures during a
rebuild/release.

## Upgrade

Run:

```sh
npx -y @bybrawe/opencode-goal@1.3.43
```

Then fully restart OpenCode and verify:

```text
/goal status
```

Existing Goal state, evidence, revisions, budgets, handoff state, and project data
are preserved.
