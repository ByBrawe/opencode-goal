# OpenCode Goal 1.3.46

Continuous/infinite Goal mode patch.

## Continuous Goal contracts

Long-running monitoring, generator, queue-processing and other intentionally
open-ended work no longer needs an impossible acceptance condition just to keep
the Goal alive.

Start a continuous Goal with:

```text
/goal process incoming work forever --continuous
```

`--infinite` is an alias for `--continuous`.

Continuous mode deliberately disables automatic verified completion. Goal-owned
prompts tell the model not to call `opencode_goal_complete`, and the host rejects
that tool before running configured checks, file verification or the independent
semantic verifier if it is called anyway.

The mode does **not** disable safety boundaries. These still behave normally:

- explicit turn, token, runtime and cost budgets;
- provider / usage limits and bounded infrastructure recovery;
- waiting-user state;
- repeated no-progress and blocker protection;
- restart recovery and compaction continuation ownership;
- user steering, `/goal pause`, and `/goal clear`.

To return a continuous Goal to normal verified completion semantics:

```text
/goal edit finish the current backlog and stop --verified
```

## Persistence, queue and visibility

The completion policy is an optional schema-v1 field. Existing stored Goals that
do not have it are treated as `verified`, so no migration is required.

Queued Goals preserve continuous mode through activation:

```text
/goal add monitor the next source continuously --continuous
/goal next
```

`/goal status`, `/goal contract` and `/goal audit` expose the mode. The native
OpenCode 2 sidebar renders `CONTINUOUS` instead of presenting a misleading
completion-proof fraction for an open-ended Goal.

## Validation

The release candidate is covered by deterministic regressions for:

- parser aliases, conflicts and explicit `--verified` reversal;
- domain completion veto while continuous mode is active;
- V1 and V2 Goal creation/edit propagation;
- ordered queue persistence and promotion;
- prompt and compaction policy;
- native sidebar rendering;
- V2 completion short-circuit before checks or semantic verification.

The usual exact-main release gates still cover Linux/Windows CI, current and
older OpenCode 2 hosts, OpenCode 1 compatibility, restart recovery, Todo
materialization, three-session handoff, sidebar rendering and publish-package
smoke.

## Upgrade

```sh
npx -y @bybrawe/opencode-goal@1.3.46
```

Then fully restart OpenCode and verify:

```text
/goal status
/goal contract
```

Existing verified Goals keep their previous behavior. Continuous mode is opt-in.
