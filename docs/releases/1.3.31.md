# OpenCode Goal 1.3.31

Durable long-Goal Todo recovery release.

## Added

- Persist OpenCode's native Todo plan at item level inside Goal state as a revision-bound advisory manifest: exact item text, status, priority, order, optional native Todo id, and a deterministic Goal-owned item key.
- Keep Goal-owned item identity stable across Todo status transitions without treating the manifest as a second live Todo database.
- Upgrade older schema-v1 aggregate-only Todo telemetry to the durable item manifest on the next current native Todo observation without a persisted schema bump.

## Restart and compaction reliability

- Preserve the last observed 50-100+ item work plan in Goal-owned persistence so a process restart or model compaction no longer reduces recovery to aggregate counts and a digest.
- Re-anchor a bounded item-level Todo rendering during compaction while keeping the full manifest persisted in Goal storage when the model-facing rendering must truncate.
- Keep repeated autonomous continuation prompts compact: ordinary continuation still carries only the aggregate Todo summary and never re-appends a large item list every turn.
- Keep `/goal edit` ownership strict. The previous manifest becomes stale for the new Goal revision, and an unchanged native Todo replay cannot silently rebind it; a genuinely rebuilt/changed plan can become current.

## Safety preserved

- Native OpenCode Todo remains the live execution-plan owner. Goal's durable manifest is recovery/reconciliation state only.
- Todo observation still creates no Goal evidence, proves no requirement, increments no host progress revision, and authorizes no scope expansion.
- A fully completed Todo manifest still cannot complete a Goal. Host checks, current trusted evidence, independent semantic verification, current Todo veto rules, constraints, budgets, user pause/steering, and revision ownership remain authoritative.
- Existing schema-v1 Goal files that contain only aggregate Todo telemetry remain readable and valid.

## Verified

- New regression coverage exercises exact 100-item text/status/order/native-id persistence, stable Goal item identity across status changes, legacy aggregate upgrade, stale revision handling after Goal edits, bounded compaction rendering, non-bloated repeated continuations, malformed manifest rejection, and non-evidentiary Todo completion.
- The exact feature head passed Actions Security Gate, CI, minimum/latest OpenCode plugin compatibility, Ubuntu/Windows lifecycle and active steering, native Todo and semantic completion, 10-turn completion, same-turn batch rejection, manual/automatic compaction, Real Host Progress, Real Restart Recovery, released Loop coexistence, and Node 20/24 packed-artifact smoke on Ubuntu and Windows.
