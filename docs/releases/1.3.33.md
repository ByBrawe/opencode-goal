# OpenCode Goal 1.3.33

Goal empty-turn fail-safe release.

## Empty assistant recovery

- Goal-owned assistant completions now require meaningful activity: non-empty text or tool/file/patch/artifact activity.
- Whitespace-only, reasoning-only, or otherwise blank completed replies no longer consume the logical Goal-turn counter.
- Empty provider attempts still contribute their real token, cost, and runtime usage, so observability and spend accounting remain accurate.
- The first consecutive empty completion gets one bounded retry. The second consecutive empty completion pauses the Goal with a visible warning instead of allowing autonomous churn.
- Tool-only work remains meaningful even when the assistant's final text tail is blank.
- Meaningful work and explicit Goal resume clear the persisted empty-turn streak.

## Persistence and safety

- `emptyTurnCount` and `lastEmptyTurnAt` are optional schema-v1 fields, so older persisted Goals remain readable.
- Persisted empty-turn fields are validated fail-closed for corrupt values.
- Empty attempts are deduplicated through the existing assistant message usage ledger, so duplicate completion events cannot increment the streak twice.

## Publish reliability

- Registry manifest and clean-installer verification now use a longer bounded retry window to tolerate npm propagation after trusted publishing.
- Reruns remain idempotent: an already-published exact version skips `npm publish` and performs verification only.

## Verified

- Exact feature-head CI covers Ubuntu/Windows unit tests, minimum/latest OpenCode compatibility, real lifecycle, active steering, semantic completion, compaction continuation, host progress, restart recovery, Loop coexistence, and Node 20/24 packed-artifact smoke.
