# ByBrawe OpenCode Goals 1.3.50 — /goalx separation, stability and verifiable completion

Release candidate: 2026-10-31 (publication only after exact-main npm provenance and registry verification).

## Foreground and native V2 stale-write recovery (#275, #276, #280)

- Fix the observed `GoalStoreConcurrencyError stale_write` when independent event/tool wrappers race with a foreground Goal writer.
- Introduce bounded (default six, maximum eight) *fresh-state* retry for stale generation writes only. Storage integrity failures, lock ownership errors, replaced Goal identities and non-stale errors still fail closed.
- Preserve the original Goal ID/revision/owner when binding V1 foreground execution/steering, so an event cannot mutate a new Goal created in the same session.
- Bind V1/V2 completion to the actual verified snapshot. Changing requirements, Todo plan, progress fingerprints, relevant evidence or declared-file results triggers rejection or bounded re-verification rather than reusing stale completion evidence.
- Re-read file evidence on retry and preserve both writers' legitimate state updates. The contribution is from [@muhammad-luay](https://github.com/muhammad-luay), [PR #276](https://github.com/ByBrawe/opencode-goal/pull/276), with independent owner CI verification in #288.

## Require real proof before marking a Goal completed (#281, #286)

- Runtime turn count and mutation fingerprints cannot alone prove a generic deliverable such as implementing a file. They remain valid evidence when the *explicit requirement itself* is about Goal-turn cadence.
- A mixed objective must satisfy both its cadence and the actual deliverable. Unrelated passing checks cannot establish a named artifact.
- Verify named deletion targets independently as absent in the real workspace. Recheck before accepting deletion evidence to detect a recreated file; reject symlinks and unsafe paths.
- Keep semantic verifier evidence, host file/command evidence and Goal revision ownership separate.

## Native OpenCode 2 compatibility (#283, #284, #285, #287)

- Validate native Goal lifecycle and restart on exact **OpenCode 2.1.4** alongside legacy supported 2.0.x host canaries.
- Widen *optional native CLI/TUI* `@opentui/core` and `@opentui/solid` peer range to `>=0.5.14 <0.8`, after **strict npm** clean-install and actual Bun TUI render tests on Windows/Linux with 0.5.14 and 0.7.0 (no `--legacy-peer-deps`).
- Independently verify packed Loop+Goal source candidates together in [Loop #193](https://github.com/ByBrawe/opencode-loop/pull/193); this is not evidence that published **Loop 0.6.9** has the unreleased new sidebar.

## OpenCode 2 `/goalx` command namespace (PR #291)

- On OpenCode **2.x**, this plugin registers `/goalx` (e.g. `/goalx status`, `/goalx audit`, `/goalx pause`) and **does not** register `/goal` in the native command catalog. This preserves OpenCode 2.2.x's built-in `/goal` command.
- On OpenCode **1.x**, the existing `/goal` command and managed legacy command bridge remain unchanged. The npm package name, existing Goal state and contracts are unchanged.
- The installer preserves user-owned `commands/goal.md`; such legacy files can still shadow OpenCode's native `/goal` until the owner reviews them. Do not automatically delete them.
- Command separation is **not** session scheduler arbitration. Avoid running the built-in Goal and `/goalx` autonomous engines in the same session. Install Loop separately; do not start a prompt Loop against an active Goal in the same session.
- CI exercises actual OpenCode 2 native direct lifecycle and the standalone Loop 0.6.10 host as separate checks; Windows Desktop GUI command discovery remains unverified.

## Installation

```powershell
npx -y @bybrawe/opencode-goal@1.3.50
```

**Compatibility warning:** OpenCode 2.2.x already ships `/goal`. ByBrawe Goals uses `/goalx` on OpenCode 2; run `/goalx status` for this plugin, **not** `/goal status` (the built-in command may interpret `status` as a new objective). Never run two autonomous Goal engines in the same session. The command rename does not prove concurrent scheduling is safe.

**Upgrade and removal:** The uninstaller removes ByBrawe package registrations, including explicit `OPENCODE_CONFIG`, while preserving other plugins, user-owned command files and existing project Goal history. Loop is independent and must be installed separately. Completely restart OpenCode after installing or upgrading.

**Limits:** This release does not claim the user-reported false completion/stall scenario [#279](https://github.com/ByBrawe/opencode-goal/issues/279) has been replayed on their production workspace. [#281](https://github.com/ByBrawe/opencode-goal/issues/281) tracks artifact-linked closure receipts, [#282](https://github.com/ByBrawe/opencode-goal/issues/282) tracks silent compaction/auth stall visibility, and [Loop #169](https://github.com/ByBrawe/opencode-loop/issues/169) tracks Windows Desktop GUI command discovery. A green CLI/TUI native host test is not proof of Windows Desktop GUI parity.

**Publication gate:** The source must pass all exact-main Windows/Linux release readiness, real OpenCode 2 host, Restart, Todo, security and native sidebar checks. npm OIDC publication, registry `gitHead` and published consumer checks must succeed before this version is reported as shipped.
